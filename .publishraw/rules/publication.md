# publication

Read .publishraw/install.json through the owning schema, then reread the current collection profile, operation, authoritative draft and actual approval observation. Resolve the configured remote from the installation repository identity and fetch the explicit publishing branch; never infer the target from the current/default branch. Before writing, verify the remote repository identity against the authenticated host; a URL-shaped string or stored numeric ID alone is not current evidence. The installation repository and publishing repository/branch must match the actual remote and operation target. Support workflow "direct" and workflow "pull-request" only. Re-evaluate current target protection before every attempt: a newly required pull request changes an unchanged approved direct intent to the pull-request route without changing its target or approval. Never bypass protection.

Before resuming any publishing, awaiting-checks-review or outcome-unverified operation, authenticate and query the configured remote branch plus the stored PR before another write. If the approved paths equal the prepared bytes, record the observed target commit as published and do not push or merge again. If the approved paths still equal their recorded baseline, the prior write is proven absent: rebuild the same approved intent on the fetched current target tree, retain unrelated remote paths from that fetched tree, and follow the protections observed now. If an approved path equals neither baseline nor prepared bytes, stop for same-item reconciliation and renewed approval. Do not discard local recovery evidence while the remote outcome remains uncertain. When an already verified publication later changed, retain its historical resultingCommit/verifiedAt evidence, describe the current differing paths, and never overwrite them merely to recreate the published state.

Before dependent item publication, inspect the actual fetched target branch for its installation record, selected collection profile, schema validator, pinned runtime and required conductor/workflow/rules. Read those blobs from the fetched remote commit and recompute the fetched profile and schema digests; compare them with the approval baseline instead of returning stored digests as current evidence. Missing or mismatched renderer/schema/instructions is TARGET_INSTALLATION_PENDING. An explicitly approved installation diff may publish first; only after its verified arrival may a separately approved dependent item re-fetch those dependencies and continue. Never combine separately approved diffs.

Call inspectDraftApproval against the reread bytes and actual observation. A normalized-equivalent result requires recorded raw inspection. Any existing valid HTTP(S) image URLs use existing-url evidence and work without a repo binding; any local-draft reference or unfinalized new image blocks. Invoke the pinned adapter validateItem with purpose: "publication" against the current installed profile and authoritative draft. For creates, the actual remote target must still be absent when baseline.targetSha256 is null; otherwise its raw digest must match. A same-item mismatch is TARGET_BASELINE_CHANGED and requires reconciliation and renewed approval. Unrelated work remains based on the fetched remote tree.

Materialize only the approved normalized text at operation.target.paths. Import normalizeApprovalText and sha256Bytes from the verified adapterRunnerEntry; set publication.preparedContentSha256 to the digest of normalizeApprovalText(current draft bytes). Run every required profile check through the helper and retain its redacted evidence. Any failed or unverified required check blocks the write.

Preserve the user's ordinary index and unrelated working changes by using a fresh temporary GIT_INDEX_FILE under ignored .publishraw/local/. Seed it from the fetched remote commit, add with literal pathspecs only operation.target.paths, and inspect the NUL-delimited staged names by diffing that isolated index explicitly against the fetched remote commit rather than the checkout's ordinary HEAD. They must be exactly equal operation.target.paths, with no drafts, local records or recovery files. Compare each staged blob with the approved bytes; for Markdown compare sha256Bytes(normalizeApprovalText(staged bytes)) with publication.preparedContentSha256. For an installation diff, verify the exact approved bounded plan paths and blob digests. Write the isolated tree and create one commit whose parent is the fetched remote commit. Verify the commit diff is still exactly the approved paths.

Immediately before any remote write, atomically record phase publishing plus publication.branch, preparedContentSha256 and attemptAt in the ignored operation record. For direct publication, push without force using the configured remote and an explicit commit-to-branch refspec; do not use an implicit current branch. Regardless of the push process result, query and fetch the remote branch again, then compare its actual remote branch bytes at every approved path with the prepared commit/content. Only that verified content permits phase published with resultingCommit and verifiedAt.

For workflow "pull-request", create or reuse one publication head branch only after recording the write attempt. Verify the base repository ID and branch equal the approved publishing target. Before the head write, atomically persist publication.head with its repositoryId, branch and commit together; the target record already preserves the upstream base. On every later attempt or recovery, compare the PR's head repository ID, branch and current SHA with those durable expected values before pushing, reusing or merging. Never create a fork implicitly. An explicitly established existing fork-head PR is usable only when its upstream base and fork head identities, current head SHA and complete changed-path/content diff match the approved intent. Search open and closed PRs for that exact head/base. Reuse one open same-intent PR; never duplicate it. A closed unmerged PR is neither published nor an open retry target: preserve its URL and report the reviewer decision or closure as a blocker instead of reopening it or silently creating a replacement.

After the head push or PR creation, record publication.prUrl and phase awaiting-checks-review. Re-read the exact PR, current base protection, required status-check contexts, check runs/combined statuses, effective reviews and unresolved-conversation requirement. Expose every pending or failed required check and the required review count. Merge only when the same head SHA remains current, all required checks and review requirements pass, conversations are resolved, mergeability is established and access permits the repository's allowed merge method. Do not use admin or token bypass. If requirements remain, stop awaiting-checks-review with the PR URL and blockers. Record intent before the merge request; after any ambiguous merge result, query the PR and target before another write.

After a permitted merge, re-fetch the configured target branch and verify its actual approved paths and normalized content against the prepared intent. Do not require the publication commit to be an ancestor: squash or rebase may produce different commits. A merged flag or closed PR alone is insufficient. Only matching target content permits phase published with resultingCommit and verifiedAt; a closed-unmerged or merged-but-mismatched result remains blocked and is never reported as published. Apply this same pull-request route to approved item, bounded installation and later bounded conversion intents.

Classify a conclusive pre-write failure such as local validation, credential rejection, DNS failure or connection refusal as a known blocker when the process evidence proves no receiver could have accepted an update; an unreadable follow-up query alone does not turn that failure into uncertainty. If the push may have reached the receiver and its result does not establish whether the ref changed, then an unreadable remote leaves phase outcome-unverified with blocker code OUTCOME_UNVERIFIED; do not push again. If the remote can be reread, compare the actual ref/content: verified arrival succeeds; proven absence is a known blocker. A later session resolving outcome-unverified must query first. Report collection, host, media and publication states separately; publication does not claim deployment. Preserve the draft, approval observation, check evidence, temporary commit identity and operation record for recovery, then remove only the temporary index after its evidence is retained.
